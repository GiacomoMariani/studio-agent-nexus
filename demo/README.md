# Demo Knowledge Base — Game Title (fictional)

These documents seed the Studio Agent Nexus demo knowledge base. They describe the
**multiplayer backend, data pipeline, and production** of a fictional online game
("Game Title" at "Game Studio"). All content is synthetic and safe for public
demonstration — no real people, studios, credentials, or data.

`DemoDocumentSeeder` loads every file in this folder on startup
and marks it `is_demo=True` (protected from deletion). PDFs are generated by
`scripts/generate_demo_pdfs.py` (reportlab, a dev-only tool).

| File | Format | Focus |

## Embedded conflicts (for the agent to detect)

The documents deliberately disagree and leave gaps so the demo can show contradiction and
risk detection. These are mirrored in `frontend/fixtures.py` (`DEMO_RISKS`).

**Contradictions**
- **Server tick rate (Critical):** architecture says 30 Hz; the fleet runbook sizes for 60 Hz.
- **Matchmaking SLA (High):** architecture targets p95 < 15 s; readiness requires p95 < 10 s.
- **Retention definition (Medium):** analytics uses a rolling 24 h window; the pipeline buckets by UTC calendar day.

**Risks**
- **Fleet ceiling (Critical):** no maximum fleet size documented for autoscaling.
- **PII retention (High):** no purge window for player-identifying event data.
- **Staging blocker (High):** load testing blocked by an unprovisioned staging environment.
- **Ad consent (Medium):** ad metrics depend on a consent flag not wired through the SDK.

## Expected demo outputs

- **Ask:** grounded answers with citations (e.g. "How does the matchmaking service work?",
  "What is the authoritative server tick rate?"); fallback on out-of-scope questions.
- **Board:** task extraction by department (Backend / Infra / Data / QA / Production) and a
  planning pass surfacing the missing work implied by the gaps above.
- **Risks:** the three contradictions and four risks above, with sources.
- **Logs:** every question logged with tokens, cost, latency, and fallback status.
